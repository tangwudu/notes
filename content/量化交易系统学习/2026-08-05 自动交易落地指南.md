# 自动交易落地指南（六大层 + 路线图 + 实战坑）

> [!abstract] 一句话总结
> 把"想自动交易"变成"能安全自动交易"，要过六层关：数据 → 执行 → 策略 → 风控 → 运维 → 合规。本文是这套系统从 0 到 1 的完整沉淀。

## 一、自动交易的六大层

### 1. 数据层
- 富途 K 线原生最低 **1 分钟**（`KLType.K_1M`）；15 秒 bar 必须订阅 `TICKER` 流自己聚合——但成本吃掉信号，不推荐
- 美股实时行情/期权盘口需要富途账户权限（LV1/LV2）
- 富途历史 1 分钟只覆盖最近数个交易日，长历史回测需第三方数据源
- 期权链历史无法任意回溯 → 策略信号用正股回测，期权 P&L 用 delta 近似

### 2. 执行层
- OpenD 本地下单延迟 ~50–200ms，对分钟级策略足够
- **市价化限价单**：买用 ask / 卖用 bid，保证成交且如实记录滑点
- 期权限价单成交率低 → 需要"撤单-改价-重挂"状态机 + 超时自动撤单
- 每笔订单写审计日志（决策归因，可追溯）

### 3. 策略层
- 方案A：ORB + VWAP + EMA 趋势跟踪（正股为主）→ 见 [[2026-08-05 日内交易策略详解-ORB趋势跟踪|策略详解]]
- 方案B：事件驱动跨式（期权）→ 见 [[2026-08-05 方案B-事件驱动跨式详解|方案B详解]]
- 核心原则：**信号必须确定性、可回测、成本可覆盖**（见 [[2026-08-05 滑点审计方法论|滑点审计]]）

### 4. 风控层（全部确定性代码，LLM 无权覆盖）
| 规则 | 参数 | 动作 |
|---|---|---|
| 日亏损熔断 | 2.5% 资金 | 全平 + 禁开 + 通知 |
| 单笔止损 | 2×ATR 或 权利金50% | 无条件退出 |
| 持仓上限 | 1–2 个头寸 | 拒绝新开 |
| 单笔风险预算 | 0.8% 资金 | 头寸 = 预算 ÷ 止损距离 |
| 期权张数上限 | 5 张/标的 | 拒绝 |
| 不过夜 | 收盘前30分钟 | 强制平仓 |
| 事件黑名单 | 财报/宏观前2h | 不开新仓 |
| kill switch | 手动文件 | 引擎每轮检查 |

### 5. 运维层
- 美股时段 21:30–04:00（北京时间夏令时），机器需稳定在线
- **每日自动调度**（cron）：交易日 09:00–09:25 ET 自动启动、16:05–16:30 ET 收盘保险，周末/节假日跳过（zoneinfo 精确判断，夏令时自动正确）
- 启动自检残留持仓；断网预案（模拟盘阶段影响可控）

### 6. 合规层
- 自动化/高频交易有监管（SEC/FINRA、MiFID II）；个人小资金风险有限
- 保留审计日志（系统已有）；不要无人值守跑实盘

## 二、路线图（Phase 0–4）

```
Phase 0  数据基建     富途订阅 K_1M → SQLite 落盘        ✅ 完成
Phase 1  回测验证     ORB/VWAP 真实1分钟历史 + 真实成本    ✅ 完成 (样本小)
Phase 2  Paper 交易   富途模拟盘全自动 + 滑点审计闭环       ✅ 运行中
Phase 3  小资金实盘   每笔 ≤ 账户1-2%, 人工每日盯审计日志   ⬜ 待样本足够
Phase 4  复盘迭代     月度得失分析 + walk-forward 调参     ⬜ 远期
```

**判断 Phase 2 → 3 的唯一标准**：模拟盘 30+ 笔真实成交，实测滑点校准后回测仍正期望，且连续 2 周无系统事故。

## 三、实战踩过的坑（真实案例，比任何教程都值钱）

| # | 坑 | 症状 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | **时区错 12 小时** | 引擎把今天当昨天、时间退出不触发 | `time.mktime` 按系统时区（北京）解析富途 ET 时间字符串 | 用 `zoneinfo("America/New_York")` 解析，兼容毫秒/字符串两种 time_key |
| 2 | **仓位爆杠杆** | 风险预算 0.8% → 106 股 SPY ≈ 4 倍账户 | 只有风险预算、没有名义值上限 | 加 `max_notional_pct=1.0`，风险与名义双上限 |
| 3 | **风控误杀正股** | "张数超限 59>5" 全拒 | `can_open` 把股数当期权张数 | 张数限制只对 option 生效 |
| 4 | **日切换崩盘** | 开盘瞬间 KeyError | `_reset_day` 清空 buf 后 `_process_bar` 又读 buf | 改为"过滤保留当天 bar"而非清空 |
| 5 | **富途 API 返参变化** | 解包崩溃 | `request_history_kline` 返回 3 元组；`order_status` 返回字符串 | 按版本兼容（3元组解包 + int/str 双容错） |
| 6 | **回测滑点失真** | 回测曲线好看、实盘不行 | 固定滑点低估成本 | 滑点审计闭环（见 [[2026-08-05 滑点审计方法论|方法论]]） |
| 7 | **pgrep 误杀** | 命令行含关键词的 bash 进程被 kill | `pgrep -f` 匹配过宽 | 改用 PID 文件 + `/proc/<pid>/cmdline` 校验 |

## 四、命令速查

```bash

bash scripts/setup_cron.sh status                       # 查看自动任务
```

## 五、关键设计原则（反复强调的三条）

1. **LLM 只做分析，不做资金安全决策**——熔断/止损/仓位全部确定性代码
2. **成本是策略的生死线**——先校准成本，再谈 edge；先正股跑通，再上期权
3. **样本不够不下结论**——30 笔交易之前，任何胜率数字都是噪声
